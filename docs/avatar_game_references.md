# 换装 / 养成类游戏的做法与对 CoFit 的启示(2026-11-04)

> 配套 [avatar_system_design.md](avatar_system_design.md)。按「渲染结构 → 槽位与内容生产 → 获取循环 → 付费 → 社交展示 → 养成」六个维度拆,
> 每节末尾给出 **CoFit 取舍**。游戏机制按我对各作品截至 2026 年中的了解整理,细节可能已变。

---

## 1. 渲染结构:换装怎么和动画共存

| 游戏 | 做法 | 要点 |
|---|---|---|
| **Among Us** | 一个豆人本体,帽子/皮肤/宠物是贴在本体上的 2D 图层 | 早期每顶帽子要为每个动作帧**手工标偏移**(hat offset),帽子一多就成了维护噩梦;后来改成按「锚点」挂 |
| **Fall Guys** | 一个豆子骨架;上装/下装是替换网格,颜色/花纹是材质参数 | **所有服装共享同一骨架**,任何动画对任何服装成立;「颜色 × 花纹 × 服装」三个独立槽位,组合数爆炸但内容成本线性 |
| **Fortnite / Roblox** | 共享骨架(Roblox 固定 R15 骨骼),皮肤是蒙皮网格,配饰是绑到骨骼上的附件 | 同上:**内容只需适配骨架,不需适配动作** |
| **Spine(Nikki 系列、大量 2D 手游的引擎)** | 「槽位 slot + 附件 attachment + 皮肤 skin」:skin 是「每个槽位放哪个附件」的一张表,骨骼动画完全不关心皮肤 | 这是 2D 换装的工业标准模型;换装 = 换表,动画不变 |
| **Duolingo** | 角色用 Rive 做,状态机驱动表情/动作 | Rive 的 2D 骨骼 + 状态机适合「少量角色、大量情绪」,换装靠 nested artboard / data binding,内容由设计师在编辑器里绑 |
| **Habitica** | 纸娃娃像素图层,**没有动画** | 换装便宜但角色是死的;放弃动画换来内容产量 |
| **Finch / Pikmin Bloom / Pokémon GO** | 3D 或 2D 骨骼,服装是附件 | 养成类普遍选骨骼附件,不选逐帧 |

**CoFit 取舍**
- 坚持「一个骨架,所有物品挂骨骼」——这就是 Spine 的 slot/attachment/skin 模型,与提案 §3 一致。Among Us 的 hat offset 之痛正是我们要避开的「每个动作重画配饰」。
- 借 Fall Guys 的三分法:**形态(body)× 颜色(bodyColor)× 花纹(pattern)** 作为三个独立槽位。花纹(条纹/圆点/渐变)只是一个 shader/clip path,**一份花纹适配所有形态,一个颜色适配所有花纹**,是最便宜的内容倍增器。提案原来没有 `pattern` 槽位,应加上。
- 把物品定义写成 Spine 的 skin 表形式:`AvatarConfig` 本质就是「槽位 → 附件 id」的表。

## 2. 槽位、层级与内容生产

| 游戏 | 槽位设计 | 要点 |
|---|---|---|
| **奇迹暖暖 / 闪耀暖暖** | 发型、连衣裙、外套、上衣、下装、袜子、鞋、头饰、耳饰、颈饰、手饰、腰饰、手持、背景……十几个槽位,**严格 z 序** | 槽位多 = 组合多 = 可卖的东西多;但每件都是全尺寸原画,成本极高,靠 gacha 回收 |
| **Fall Guys** | 上装、下装、颜色、花纹、面部、名牌、昵称牌、庆祝动作、胜利动作 | **「庆祝动作」「胜利动作」是可卖的槽位** —— 动作本身是商品 |
| **Among Us** | 颜色、帽子、皮肤(衣服)、面甲、宠物、名牌 | 宠物 = 跟随本体的独立小动画,人气极高、制作独立 |
| **Fortnite** | 皮肤、背饰、镐、滑翔伞、表情、涂装、加载画面、音乐 | 「表情/动作」是最大的非皮肤品类 |
| **Zwift** | 车架、轮组、头盔、骑行服、袜子、眼镜、手套 | 运动类游戏用**运动装备**当槽位,和运动主题天然一致 |

**CoFit 取舍**
- 槽位定稿建议(按 z 序从后到前):`aura(光圈/地面光效)` → `pet(跟随宠物,P4+)` → `body` → `pattern` → `bodyColor` → `legwear/armband(四肢色环)` → `face` → `eyewear` → `headwear` → `handheld(待机手持)` → `celebration(完成动作特效)`。
- **把「动作/特效」做成商品槽位**(Fall Guys/Fortnite 的核心收入来源):`celebration` = finish 阶段的庆祝(烟花 / 双跳 / 比心),`aura` = 运动中的粒子/拖尾。这两种是**纯程序动画,零原画成本**,很适合我们的矢量引擎。
- 运动装备化:发带、护腕、护膝、运动眼镜、哑铃配色(道具也能换色!)——道具是 clip 的一部分,给它们一个 `prop_skin` 槽位,「金色哑铃」这种东西制作成本是一行颜色。
- 不做暖暖式十几个全尺寸原画槽位,46px 的小人根本看不出来;槽位数控制在 10 个以内,每个槽位的差异必须在 46px 可见(剪影测试同样适用于物品)。

## 3. 获取循环:怎么让人「想要」

| 游戏 | 机制 | 要点 |
|---|---|---|
| **Zwift** | 骑行产生 **Drops**(软货币),Drop Shop 买装备;**等级**解锁基础装;**挑战**(爬完珠峰高度解锁 Tron 车)解锁稀有装 | 软货币 = 运动量的直接映射,「骑得越多买得越多」;稀有装只能靠运动拿,是炫耀资本 |
| **Habitica** | 完成任务得金币买装备;装备加属性(轻度 pay-to-win 风险) | 把习惯行为变成货币来源,但「装备影响数值」在健身 App 里会扭曲动机 |
| **Pikmin Bloom** | 走路长苗;**每月限定装饰皮克敏**只在当月参与才拿得到 | 限时 = 促活;错过即永失 |
| **Finch** | 自理任务产 energy,鸟成长;服装用 rainbow stones 买(可赚可买) | 「可赚也可买」的双通道,免费玩家靠时间、付费玩家靠钱 |
| **Pokémon Sleep** | 睡得好 → 研究点数 → 换物品 | 行为本身的质量变成货币 |
| **Among Us / Fall Guys** | 季票 / 赛季通行证:两条轨道(免费 + 付费),按赛季进度解锁 | 把「持续在线」和「付费」绑在同一条进度条上 |
| **奇迹暖暖** | gacha(抽卡)为主 | 高 ARPU,但 Apple 要求公示概率(3.1.1),且与「健身 App」调性冲突 |

**CoFit 取舍**
- **引入一种软货币**(暂名「汗滴」,名字待定),来源只有一个:**完成卡片打卡**(按时长折算,`users/{uid}/sessions` 已有数据,可客户端现算累计而不新开集合;若要防重放再上 Functions)。用途:买免费层物品。这是 Zwift Drops 的做法,把「运动量」直接映射为「购买力」。**软货币不可用钱买**,保证「某些东西只能靠练」的叙事成立。
- **成就解锁**保留(Zwift 挑战):连续打卡、累计时长、类型精通(力量 50 次)、社交(与 5 个不同的人同房运动)。成就物品**不进商店**,只能拿。
- **限时**:每月一件「月度物品」,当月打满 N 次自动获得(Pikmin Bloom 月度装饰)。实现上就是 `unlock: monthly(yyyy-MM, n)`,目录随发版带未来 2–3 个月的物品,Remote Config 控上架。
- **不做 gacha**;**暂不做赛季通行证**(需要赛季运营节奏,团队现在没有)。
- 物品不影响任何数值(反 Habitica):CoFit 的运动不该因为穿了什么而「更有效」。

## 4. 付费形态

| 游戏 | 形态 | 要点 |
|---|---|---|
| **Fall Guys / Fortnite / Among Us** | 硬货币(Show-Bucks / V-Bucks / Stars)+ 商店轮换 + 捆绑包 + 赛季通行证 | 硬货币让定价脱离 Apple 价格档;商店每日轮换制造稀缺 |
| **Zwift** | 订阅(软件本身)+ 虚拟装备不单卖 | 装备是留存手段不是收入 |
| **Finch** | 订阅 Finch Plus(更多装饰、小部件)+ 少量一次性包 | 养成类的订阅通常「功能 + 装饰」捆绑 |
| **Pokémon GO** | 硬货币 + 单件服装直售(约 ¥10–40) | 单件直售在 3D 大作里也成立 |
| **Duolingo** | 订阅为主,角色服装是订阅的附属福利 | 形象当订阅赠品 |

**CoFit 取舍**
- 第一步仍按提案:**非消耗型形象包直售**(Pokémon GO 的直售 + Fall Guys 的捆绑)。不引入硬货币:硬货币是消耗型 IAP,带来余额、退款、未消费权益等一整套审核/合规负担,现阶段不值。
- 预留**订阅**位置(Finch Plus / Duolingo 模式):将来若做「CoFit+」(更多统计、Live Activities、房间上限),把每月一件订阅专属物品捆进去。
- **商店轮换**(每周推荐位)用 Remote Config 实现,目录不变,只变展示;对冲「所有东西一直在卖」的平淡。
- 定价建议对齐 App Store 国区常见档:单件 ¥6,形象包 ¥18–¥30(4–6 件,含 1 件包限定)。

## 5. 社交展示:换装的意义在于被看见

| 游戏 | 做法 |
|---|---|
| **Among Us** | 大厅里所有人的装扮一眼可见;**颜色 = 身份**(「红的是内鬼」),装扮不干扰身份识别 |
| **Fall Guys** | 淘汰/夺冠时的「庆祝动作」全场可见,是最被炫耀的商品 |
| **Zwift** | 骑行时旁边人的车和服一目了然;稀有装备的「这人爬过珠峰」信号 |
| **Pokémon GO** | 好友列表显示对方形象;礼物互送 |
| **奇迹暖暖** | 搭配评分、好友围观、公会展示 |

**CoFit 取舍**
- 房间就是我们的「大厅」:换装的全部价值在房间里兑现,所以 **presence 必须带形象**(提案 §5.2 选 a)。
- 借 Among Us:**身体色 = 身份**,状态改走头环/光圈(提案 §5.6)。Among Us 证明了「颜色当身份、装饰叠在上面」不会损害可读性。
- 借 Fall Guys:**完成动作的庆祝特效全房间可见**,这是最值得先做的付费物品之一。顺手把 STATUS.md 里「能量爆发粒子」这个未做润色收进 `celebration` 槽位。
- 「新物品上身」在房间里播一次 windup burst + chip「换了新装」,给炫耀一个瞬间(Zwift 也有换装提示)。
- 我的页 hero 区展示全尺寸形象(78px hero 已有),邀请卡上的小人也用真实形象(现在是静态剪影,改成用邀请人的 `avatarConfig`,数据在 `users/{uid}` 可读)。

## 6. 养成:角色本身要「长」

| 游戏 | 做法 | 要点 |
|---|---|---|
| **Finch** | 鸟从蛋到成鸟,按自理任务成长;成长是视觉上明显的 | 「养」的对象是角色本身,服装只是附加 |
| **Pikmin Bloom** | 皮克敏从苗到成体;步数是养分 | 行为量 → 可见成长 |
| **Tamagotchi / 旅行青蛙** | 不照顾会退化 / 会出门 | 损失厌恶;健身 App 要慎用负反馈 |
| **Zwift** | 等级 1–60,升级解锁装备 | 等级是养成,装备是奖励 |
| **Duolingo** | 连胜(streak)是核心养成数字;冻结道具是付费点 | 「别断」比「变强」更有效 |

**CoFit 取舍**
- 增加一个**小人等级**(由累计运动分钟数现算,阈值表进目录),等级只做三件事:① 解锁部分免费物品;② 头环从 1 环到 2 环到 3 环(视觉成长,所有人可见);③ 我的页显示。不做属性、不做数值。
- **连胜**(streak)在小人上可见:连续 7 天以上光圈常亮微粒,断了就没 —— Duolingo 的「别断」。不做「连胜冻结」这种付费道具(健身 App 里卖「假装你练了」不合适)。
- **不做退化/惩罚**(旅行青蛙式的离开或 Tamagotchi 式的变丑):久坐本身已经够内疚了,App 不该再踩一脚。挂机好友用透明度表达即可(已有 `avatarInactive`)。
