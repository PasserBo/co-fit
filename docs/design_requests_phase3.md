> **阅读顺序**:先读 §0 设计系统上下文,再逐条设计。每个条目都列出了数据模型约束与完整交互流(含空态/加载/错误态)——**设计必须覆盖列出的所有状态**,字段与校验规则不可更改(它们已是线上行为)。

## 0. 设计系统上下文(必读)

### 产品一句话
CoFit 是「虚拟健身房」社交健身 App:好友以虚拟小人形式出现在共享房间,实时看到彼此运动状态,通过「打出动作卡牌」开始运动。核心隐喻:**房间(空间感)+ 卡牌(游戏感)**。

### 视觉语言
- **深色单主题**(无浅色模式)。背景 gray-900 `#181B22`,表面 gray-850 `#22252E`,品牌主色 lime-400 `#C8F24B`(主 CTA/选中/活跃),danger coral-500 `#E8705F`。
- **完整 token 表见既有定稿 `#13a`**(docs/design_reference.html);新设计**只许使用该表内的颜色/间距/圆角**,确需新值须单独标注「新 token 提案」。
- 间距刻度 4/8/12/16/20/24/32;圆角 4/8/12/16/20;分隔线 white @7–9%;淡底=主色@16%,淡描边=主色@40%。
- 字体 Space Grotesk;标题 w700,标签 w600。
- **动作类型四色**(卡牌色条/状态色,不可增减):strength=coral `#FF7A59`、cardio=lime `#C8F24B`、core=amber `#F2C14B`、flexibility=blue `#8FBAFF`。

### 既有定稿(风格基准,新设计必须与之同族)
- `#6b` 房间主界面:全屏沉浸场景、漂浮气泡小人、底部扇形手牌、无底部导航
- `#12b` 牌库页:左上悬浮 dock、分类分区卡牌网格、动作卡解剖(顶部类型色条+图标块+名称+时长+右上来源徽章)
- `#13a` token 表

### 导航与容器惯例(硬性)
- **无底部导航栏**。全局三 tab(房间/牌库/我的)走左上**悬浮 dock**(收起为单图标,点击展开)。
- 工具型流程用**底部 sheet**(圆角 radiusLg=16 顶角,表面色 bg.surface):现有先例=建房 sheet、房间操作 sheet、牌组切换 sheet。
- 层级更深的浏览型页面用 push + 顶部返回。
- 危险操作:**独立红字卡片或红字行**(先例=我的页「退出登录」),二次确认用系统 AlertDialog。
- 可点击目标 ≥44×44;验收视口 375×667 / 390×844 / 430×932;textScale 1.3 不溢出。

### 既有可复用组件(优先复用,不要重新发明)
| 组件 | 说明 |
|---|---|
| ActionCard | 动作卡:类型色条、图标块、名称、时长、来源徽章(官方灰/**自建**/好友蓝);支持 selected/editing(带移除角标)态 |
| DeckListBody | 「我的卡组」tab 的牌组行式总览:叠牌缩略图+名称+张数/预估时长,行内展开显示卡片缩略与「加卡」虚线瓦片 |
| DeckSwitcher | 房间主界面的牌组切换 popover/sheet |
| _SettingsGroup/_SettingsRow | 我的页设置分组行(图标块+标签+右侧值+可选 chevron) |
| RoomActionsSheet | 房间操作 sheet(现只有成员「退出房间」一项) |

## A 类:功能完备、完全没有 UI(优先级从高到低)

### A1. 牌组管理(新建/改名/加卡移卡/排序/删除)

**入口**:牌库页「我的卡组」tab(现有 DeckListBody,交互目前全是 SnackBar 占位)。

**数据模型**(不可改):
- 牌组 = `{id, name, cardIds}`。name 1–20 字符;cardIds **有序**(= 房间扇形手牌的展开顺序)且**允许同一张卡重复出现**(刻意设计:一组里可以排两次深蹲)。
- 张数、总时长、缩略配色都由 cardIds 关联卡牌现算,不存储。
- 「当前使用中」牌组是用户级状态;**删除当前使用中的牌组时,系统自动把"当前"顺移到剩余第一组**(全删光则无当前牌组)——设计需要表达这个结果(如 toast 或列表上的"使用中"标记迁移)。

**需要设计的交互流**:
1. **新建牌组**:入口(列表底部/空态 CTA)→ 命名(1–20 字,超限/空名内联报错)→ 创建成功进入该组(空组合法,"先建组后加卡")。
2. **牌组详情/编辑**:改名;卡片列表按 cardIds 顺序展示;**拖动排序**;移除某张卡(注意同卡重复时只移除被操作的那一张);「加卡」→ 从全部可用卡(官方+自建)中多选加入,同卡可再次加入。
3. **删除牌组**:危险操作,二次确认;确认文案需说明"若为当前使用中,将自动切换到××"。
4. **设为当前使用**:牌组行上的显式动作(现在只能在房间的 DeckSwitcher 里切)。

**状态**:空态(一个牌组都没有:引导新建)、空组(有组无卡:突出加卡)、加载失败(重试)。

### A2. 创建/删除自建卡

**入口**:牌库页顶部横幅「创建卡片」(现 SnackBar 占位;过程稿 `#12a` 有创建表单方向可参考,未定稿)。

**数据模型**(不可改):
- 表单字段:**名称**(1–20 字,必填)、**类型**(四选一:strength/cardio/core/flexibility,决定卡面色条)、**时长**(秒,>0;建议 UI 用常用档位 30s/45s/60s/90s/2min + 自定义)、**强度标签**(可选短文案,如「中等」)。
- 创建后卡片带**「自建」来源徽章**出现在牌库(ActionCard 已支持渲染),可加入任意牌组、可在房间打出。
- **删除自建卡**:会**自动从所有牌组中移除该卡的全部引用**——确认弹窗必须告知这一点(如"该卡将同时从 2 个牌组中移除")。官方卡不可删除。

**需要设计**:创建表单(sheet 或 push 页,遵循容器惯例)+ 表单校验错误态 + 创建成功回牌库(新卡定位/高亮)+ 自建卡的删除入口(卡片详情或长按菜单——卡片详情页本身也无设计,可一并设计最小版:大卡预览 + 加入牌组 + 删除)。

### A3. 房间管理(房主侧:编辑信息/解散)

**入口**:房间主界面顶栏 `⋯` → RoomActionsSheet。现状:成员看到「退出房间」;**房主只看到一行灰字"你是房主,暂不支持退出或解散房间"——这行要被真正的房主操作替换**。

**数据模型**(不可改):
- 可编辑:房间名(非空)、描述(可空)、可见性(`public`=公开 / `unlisted`=仅邀请,当前文案「公开/仅邀请」)。
- **解散房间**:删除房间,所有成员失去访问(成员端下次进入时自动清理,无实时踢出通知)。危险等级最高:建议二次确认 + 输入房间名或明确的不可逆警示。
- 房主**不能退出**房间(只能解散);**踢人和房主移交功能不存在,不要设计**。

**需要设计**:RoomActionsSheet 的房主版(编辑信息入口 + 解散入口)+ 编辑信息表单(可复用建房 sheet 的表单布局)+ 解散确认流 + 解散后的去向(回到剩余房间或空态)。

### A4. 运动历史列表

**入口**:我的页「运动」分组(现有 累计时长/完成动作 两行统计)→ 点击进入历史列表页(push + 返回)。

**数据模型**(不可改):
- 每条记录:`{动作名 templateName, 类型 actionKey(映射四色), 时长 durationSec, 开始 startedAt, 完成 completedAt}`,按完成时间倒序,**最多取最近 100 条**。
- ⚠️ 记录里只有 roomId 没有房间名,且房间可能已解散——**默认不展示房间信息**(或作为次要信息显示"房间已解散"回退,设计自行取舍但要处理缺失态)。
- 记录**只增不改不删**,不要设计编辑/删除入口。

**需要设计**:列表页(建议按日期分组,每条=类型色点/条 + 动作名 + 时长 + 完成时刻)+ 空态(新用户:引导去打出第一张卡)+ 100 条上限的收尾处理(列表尾注"仅显示最近 100 条"即可)。加分项:顶部小结区(本周次数/时长)——数据可现算。

## B 类:已有功能性 stub UI、待正式视觉设计(可与 A 类同批或后置)

这些页面**功能可用、token 合规**,但布局是工程兜底,无定稿:

| 页面 | 现状 | 设计要点 |
|---|---|---|
| 登录页 | 品牌字 + Google 按钮 + 「或」分隔 + 邮箱折叠表单 + 忘记密码 | **必须为 Apple 登录按钮预留最上方位置**(黑白 HIG 样式,后续启用);品牌区可强化(小人/卡牌元素) |

| 建房 sheet | 表单(名称/可见性/描述)→ 成功态=链接卡片 + 分享/复制 CTA | 「创建即邀请」是核心叙事,成功态的分享 CTA 是主角 |
