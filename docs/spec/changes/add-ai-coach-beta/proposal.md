# Proposal: 在运动历史页试用 beta「AI 教练」——根据自己的运动记录提问,教练用可交互的卡片回答

> State: in-progress · Updated: 2026-11-18

## Intent

运动历史页今天只能看列表和一张「本周」小结卡,用户想知道「这周练得够不够」「下次该练什么」只能自己数。Flutter 刚发布的生成式 UI 协议(A2UI)让模型直接回一张可交互的卡片(计划、总结、单选问卷)而不只是文字,值得在一个低风险的页面上试一试效果。

本 change 是**试验**:只在运动历史这一个页面、只对开放了 beta 的用户出现,默认关闭。怎么知道它值不值得继续:每次会话都留下完整日志(问了什么、模型多久开始回、多久出第一张卡、卡片有没有渲染失败、用户点了什么),由开发者导出后对比。

## Scope

In scope:
- 运动历史页出现「AI 教练 Beta」入口,仅对开放了 beta 的用户可见。
- 教练页:几条预置问题 + 自由输入;教练的回答可以是文字,也可以是卡片(列表、计划、表单、单选等),卡片上的按钮/输入会发回给教练继续对话。
- 教练只能看到用户最近的运动记录(最多 100 条,与运动历史页同一份),第一次使用前明确告知「最近的运动记录会发送给 AI 服务」,用户同意后才可提问。
- 每次会话的全过程记录在设备上,教练页可「导出日志」通过系统分享发出。
- 请求失败、模型回了无法显示的卡片时,对话里显示错误,用户可以重新提问。

Out of scope:
- 教练**不能**改动任何数据(不建卡、不改牌组、不写运动记录)。
- 对话不保存:离开教练页即清空,下次进来重新开始。
- 不做语音、图片输入;不做自定义卡片组件(只用协议自带的基础组件)。
- 不对普通用户开放;正式开放前需另行更新隐私说明(见 tasks M3)。

## Capabilities

- `ai-coach`(new)

## Approach

只用协议自带的基础组件目录,模型经由项目现有的云服务调用(App 内不放任何密钥)。入口与教练页都在动作/运动记录现有的页面体系里,beta 开关走现有的远程开关,默认关;开发构建里始终可见以便试用。

## Decisions
- 2026-11-18: 不另建实验 App,直接集成进 CoFit,只在运动历史页作为 beta 功能 — 单人项目,在真实数据与真实页面上试才看得出效果。
- 2026-11-18: 模型走云服务代理调用,不把模型密钥编进 App — 上架包里放密钥等于公开。
- 2026-11-18: 先用流式 JSON 格式(边生成边渲染),紧凑格式(Express)留作对比项 — 紧凑格式要等整段回答结束才渲染。

## Open questions

- 试用结论之后:扩展到房间结束运动后的总结卡,还是止步于运动历史页?
