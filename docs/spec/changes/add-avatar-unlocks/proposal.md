# Proposal: 坚持运动让小人成长——累计出牌和连胜里程碑解锁小人的新动作与配色

> State: idea · Updated: 2026-11-20

## Intent

CoFit 和其他运动记录 App 最大的不同是虚拟小人。Finch、宝可梦 Sleep、Pikmin Bloom 证明了「为了它而回来」的情感依恋比抽象徽章更有效。把运动的奖励落在小人身上,单人时有收集和成长的动力;有好友在线时,解锁的东西又能在房间里被看到,成为社交展示——单人路径和社交路径用同一套东西。

怎么知道有效:解锁里程碑前后的出牌频率、已解锁用户的留存。

## Scope

In scope:
- 一组里程碑(累计出牌数、连胜长度、四种类型都打过等),达成即解锁小人的新待机动作、庆祝动作或配色。
- 达成时有解锁时刻(小人展示新东西)。
- 一个查看已解锁 / 未解锁及解锁条件的地方。
- 用户可以选择装备哪个已解锁的外观 / 动作;好友在房间里看到的是我装备的样子。
- **只奖励、不惩罚**:断连或长期不来,小人最多表现得「有点无聊」,不会失去已解锁的东西。
- 里程碑条件与奖励内容是独立维护的清单,增删改不需要改判定与展示逻辑。

Out of scope:
- 付费外观、抽卡、限时活动(调研 L3)。
- 惩罚式机制(掉血、小人生病)——明确不做(调研 L5)。
- 独立的抽象徽章墙(调研 M3 建议并入本 change,不另起)。

## Capabilities
- `avatar-unlocks`(new)

## Approach

小人的「动作是数据不是代码」,新动作的边际成本低;但小人目前只有动作,没有「外观」和「已解锁」的概念,需要新的数据模型(与 `docs/avatar_bean_spec.md` 对齐)。里程碑判定依赖 `add-workout-streak` 的个人运动汇总。解锁表像官方卡片一样做成一份由仓库维护的清单。

## Decisions
- 2026-11-20: 由运动记录竞品调研(H4,并入 M3 徽章)立为提案 — 小人是 CoFit 独有的留存杠杆,奖励落在小人身上而非抽象徽章。
- 2026-11-20: 指标、目标值、规则参数都是**可随时调整的内容**,本系列不在提案里定死;要求系统足够解耦——计量方式、目标、连胜规则、解锁表、提醒文案各自独立可换,改一处不牵动其他部分 — 用户:先把系统做出来,再决定提供什么内容。

## Open questions
- 好友能否看到我的里程碑本身(如「第 100 张卡」),还是只看到装备的外观?
- 首批具体解锁什么:内容决定,不阻塞系统实现(配饰类需要新美术与骨架挂点,届时再评估)。
