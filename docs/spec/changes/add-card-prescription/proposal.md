# Proposal: 动作卡自带「做多少」——强度加一个大致的量(次数 / 距离 / 重量),并随运动记录保存

> State: in-progress · Updated: 2026-11-25

## Intent

一张动作卡现在告诉用户的只有「做什么」和「做多久」:卡面是名字、类型、时长,外加一个强度标签(轻松 / 中等 / 挑战)。**做多少**——几个、多远、多重——卡上没有,运动记录里也没有,所以回看时只知道「深蹲 1 分钟」。

原本的设想是卡片数据本身就带强度和一个大致的描述(次数 / 距离 / 重量等)。数据上已经留了位置(卡片的「强度基线」是一个可以放多项内容的结构),但目前官方的 32 张卡和自建卡都只填了强度标签一项,这个设想没有被做出来。

「量」是出牌**之前**就定好的东西,不是做完再回忆着填的——所以它属于卡片,不属于 memo(`add-workout-memo` 已据此去掉完成后填次数)。

怎么知道有效:带「量」的卡被打出的比例;回看记录时能否一眼看出当时做了多少(主观判断);之后「上次这张卡」类功能能不能直接用上这份数据。

## Scope

In scope:
- 卡片除了强度标签,还能带大致的量:每一项是「数值 + 单位」,种类有次数、重量、距离;全部可选,一张卡可以带几项。
- 卡面、卡片详情上看得到这个量。
- 自建卡的表单里可以填。
- 官方卡补上各自的量(内容)。
- 完成一张卡时,把当时卡上的强度和量随运动记录一起保存;运动历史和 memo 详情里显示。之后改卡不影响已有记录。
- 没有填量的卡照常可用,只是不显示。

Out of scope:
- 完成后再填实际做了多少(用户明确不要)。
- 个人纪录、进步曲线。
- 「上次这张卡」的展示(调研 §9 方案三,另立;它会用到本 change 保存下来的数据)。
- 按用户水平自动调整卡上的量。

## Capabilities
- `action-cards`(modified:卡片的内容与展示)
- `workout-history`(modified:记录里带出当时的强度与量)

## Approach

卡片的强度基线从「只有一个标签」扩成「标签 + 量」。官方卡的内容在卡片模板的唯一事实源里补,推送 main 后由现有流程同步。自建卡的权限规则已经允许这个结构里放更多内容,不需要改;运动记录的规则锁了字段,要新增「当时的强度与量」需要改规则(按惯例先给用户看 diff)。记录保存的是完成那一刻卡上的内容的副本,而不是指向卡片——卡片以后被改或被删,记录仍然看得到当时做了什么。

## Decisions
- 2026-11-25: 立为提案 — 用户:次数不应该是运动完后才填的;原本的设计是运动卡本身的数据里就含有强度以及一个大致的描述(次数 / 距离 / 重量等),而不是现在只有运动时间。
- 2026-11-25: 现状核对(代码与数据)— 卡片有「强度基线」结构,官方 32 张卡与自建卡都只填了强度标签;卡面只显示时长与强度标签;运动记录不保存强度。
- 2026-11-25: 量用**数值 + 单位**;都是可选的;一张卡可以同时有次数、重量、距离等几项(多选);官方卡按运动内容随手填一版 — 用户。
- 2026-11-25: 开始实现。用户没有回答的几个问题按以下默认做法(agent 定,用户未确认):出牌时不能临时改这次的量;量只是卡上的参考,倒计时照旧按时长走;以前的记录不补量,回看时不显示。
- 2026-11-25: 官方卡的内容:21 张按动作填了次数(弯举、推举另带重量,原地跑、踏步填距离);平板支撑、靠墙静蹲和拉伸类 11 张按时间做,不填量 — agent 随手填的起步值,随时可改。
- 2026-11-25: 强度评级沿用卡片上已有的强度标签(轻松 / 中等 / 挑战),不另加一套;它是自由文字、可选,随时能换成别的分法;完成时随记录保存一份 — agent 的做法。用户的顾虑记在这里:想让 App 不那么认真、所有人都能参与;强度可能引起攀比,让 App 变成只适合高强度的人;好处是一个概览,进了牌组不用细看内容就能打出。
- 2026-11-25: 不要「组数」— 用户:对力量训练来说,一张卡就是一组。
