# Proposal: 小人页——把「小人」和「用户」分开,运动记录归小人,让人不运动也想打开看一眼

> State: idea · Updated: 2026-11-25

## Intent

现在「我的」页把所有东西混在一起:资料、房间入口、账号、关于,以及两行「累计时长 / 完成动作」。运动记录的入口混在一排菜单行里,像设置页里的某个数据查看功能——这不是一个运动 memo App 该有的样子。

CoFit 有「虚拟角色」。屏幕上在运动的是小人,所以把**运动记录绑在小人身上**是自然的;而账号、隐私、通知这类东西属于**用户**。把两者分成两个地方:

- **小人页**:小人本身 + 它做过的运动(记录、memo、进度、连胜),以后还有换装、心情等。
- **设置**:账号、资料、隐私、关于、删除账号。

好处是强化「养成角色」的感觉:小人的详情页会随着功能增加而有越来越多可看的东西,目标是变成**「就算不运动,也想打开来看一眼小人的状态」**。

怎么知道有效:小人页的打开次数 / 活跃天数;没有出牌的日子里小人页被打开的比例(依赖 `add-usage-analytics`)。

## Scope

In scope:
- 新增「小人页」作为一级页面,取代导航里的「我的」;页面以小人为主角。
- 运动记录(时间线、memo、今日进度)从「我的 > 运动」移到小人页,成为它的主要内容。
- 原「我的」页里属于用户的部分(资料、房间入口、账号、法律文档、删除账号)移到「设置」,从小人页进入。
- 小人页的内容按可增减的区块组织(与今日面板的模块同一思路),以后加换装、心情、连胜、成长不需要重做页面。
- 从今日面板到小人页有一步可达的路径。

Out of scope(各自另立 change,本提案只留位置):
- 换装 / 外观自定义。
- 小人的心情或状态系统。
- 连胜与日历(`add-workout-streak`)、成长解锁(`add-avatar-unlocks`)——它们的展示位置改为小人页。
- 好友查看别人的小人页。

## Capabilities
- `character-page`(new)
- `workout-memo`(modified:回看入口从运动历史页改为小人页)

## Approach

领域上分成两块:**角色**(小人的外观、动作、运动记录与由记录派生的一切)与**用户**(账号、资料、偏好、所属房间)。界面按同样的线划分。第一版小人页可以很薄——小人 + 今日进度 + 记录时间线,其实就是把 `add-workout-memo` 做好的时间线换一个更显眼的家,再把用户相关的行搬去设置。之后的换装、心情、连胜各自作为一个区块接进来。

## Decisions
- 2026-11-25: 立为提案 — 用户:入口混在菜单行里,不像运动 memo App;把「我的」与「设置」区分开,把运动记录与小人绑定,user 与 character 两个领域划分清楚,强化养成角色的感觉。
- 2026-11-25: 调研 §9 的方案一(memo 在今日面板里记)与方案二(记录有一个专门的地方)都采用;方案二里「专门的地方」不做成导航里的「记录」槽位,而是小人页 — 用户的建议。
- 2026-11-25: 先做方案一(`add-workout-memo`),本提案之后再做 — 用户决定的顺序。

## Open questions
- 导航的三个槽位怎么变:房间 / 牌库 / **小人**(设置从小人页右上角进入),还是另有安排?
- 「小人」在界面上叫什么(小人 / 豆豆 / 我的小人 / 用户给它起的名字)?
- 第一版小人页除了记录还放什么:只放小人 + 今日进度 + 时间线,还是同时带上累计数字?
- 在房间页点自己的小人现在是展开 / 收起今日面板;小人页的入口放在哪里才不和它冲突(今日面板里的进度环、面板上的一个模块、导航槽位)?
- 「牌库」属于角色还是用户(牌组是小人会做的动作)?本提案默认不动。
