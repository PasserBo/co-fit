# Design: add-daily-card-goal

> 行为见 [specs/daily-goal/spec.md](specs/daily-goal/spec.md)。本文只写怎么搭。

## 1. 四个互不依赖的部分

| 部分 | 是什么 | 怎么换 |
|---|---|---|
| 计量方式 | 输入「今天完成的运动记录」,输出一个整数和一个单位 | 实现同一个接口,按 id 登记;内置 `cards`(张)、`minutes`(分钟) |
| 目标 | 默认值 + 可选值清单 + 用户在本机选的值 | 默认值与可选值在配置里;用户的选择按「用户 + 计量方式」单独保存 |
| 今日进度 | 纯函数:(记录、现在、计量方式、目标)→(当前、目标、单位) | 不需要换 |
| 展示 | 只认「当前 / 目标 / 单位」,不知道计量方式是什么 | 换界面不动前三者 |

换计量方式时,用户在旧计量方式下选的目标不会被套到新计量方式上(按计量方式分开保存)。

## 2. 配置

沿用远程开关机制,新增字符串参数 `daily_goal_config`;空串 = 内置默认值:

```json
{"metric": "cards", "defaultTarget": 2, "choices": [1, 2, 3, 5, 8]}
```

- 非法 JSON / 不是对象 → 整份用默认值;单个字段缺失、类型不对、数值 < 1 → 只有那个字段用默认值;不认识的 `metric` → `cards`。永不抛出。
- 用户保存的目标不在 `choices` 里(远程清单后来改了)时仍然沿用,并在选择面板里多显示这一项。

## 3. 「今天」

- 以设备本地时区的日历日为准,按运动的**完成时间**归日。
- 「今天是哪一天」是一个会变的值:在下一个本地零点由定时器更新,回到前台时也重新核对(定时器在后台不可靠)。
- 记录来源是现有的「最近 100 条运动记录」。一天内超过 100 次时进度会少算,目前不处理。

## 4. 目标的保存

只存本机(每个用户、每种计量方式一个键)。不写云端:不需要改数据库权限,也不引入跨设备合并问题;代价是换设备后回到默认值(规格里已写明)。账号删除时本机键不清理(不含个人数据,只是一个数字)。

## 5. 与完成庆祝的配合

模块自己维护「正在显示的进度」,与算出来的进度分开:

1. 第一次拿到数据:直接显示,不播动画。
2. 算出来的进度变大:先不动;等宿主的庆祝节拍(`celebrations` 变化)到来后,再过 `celebrationDelay(模块 id)` 把显示值滚到新值。
3. 等待超过 `dailyProgressBeatTimeout` 仍没有节拍(庆祝没播、记录来自别处):直接滚到新值。节拍先于新记录到达(记录写入比动画慢)时,新记录一到就立即滚。
4. 显示值从「未达成」滚到「达成」时播一次达成反馈(进度环强调 + 触感)。目标被用户改动导致的达成不播(第 2 步只对「进度变大」生效,目标变化直接套用)。
5. 进度变小(过零点)或目标变化:直接套用,不播动画。

小人的庆祝沿用现有的完成动作,不新增达成专用的动作(以后想区分可以单独加一条 clip)。

## 6. 今天还没开始

进度为 0 且今日推荐有卡时,模块副标题提示从今日推荐开始,点模块正文 = 调用宿主的「手牌停在某张卡」+「收起面板」,与今日推荐模块同一条路径。其他状态下点正文没有动作;调整目标始终走模块右侧的按钮。

## 7. 布局

内置默认布局的模块顺序改为 `["daily_progress", "recommendation"]`。远程配置了 `home_sheet_layout` 的不受影响(需要手动加上 `daily_progress`)。

## 8. 新增 token(起始值)

| token | 值 | 用途 |
|---|---|---|
| `size.progressRing` | 44 | 进度环直径 |
| `borderWidth.progressRing` | 4 | 进度环线宽 |
| `motion.progressRoll` | 600ms | 数字与进度环滚到新值 |
| `motion.goalReachedPulse` | 500ms | 达成时进度环强调一次 |
| `motion.dailyProgressBeatTimeout` | 2500ms | 等不到庆祝节拍时直接更新 |
| `decor.goalReachedPulseScale` | 1.18 | 达成强调的放大倍数 |
