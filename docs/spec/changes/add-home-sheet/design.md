# Design: 今日面板 — 小人上台、动画与模块容器

> 2026-11-21 · 对应提案 accepted。表里的数值都是起始值,全部进 token 或配置,上机后再调。

## 1. 原则

1. **一个进度值驱动台子相关的一切。** 面板展开程度 `p`(0 收起 → 1 展开)是唯一事实源:面板位移、手牌下沉、好友区域收缩、模块出现、站在台上的小人的高度都由 `p` 算出。`p` 由手指直接控制,或由可随时改目标的弹簧推动,所以任何时刻都能被打断。
2. **位置和姿势分开。** 小人「在哪」(漂浮点 / 台上 / 空中)由房间页的一层负责;小人「什么姿势」仍然是 clip 数据,由编排器决定。上台不打断正在播放的运动 loop。
3. **漂浮 vs 站立就是选中态。** 未选中的待机是上下浮动;台上的待机是脚踩台面、只有呼吸。不再加别的选中标记。
4. **先反馈,后移动。** 点击后小人在同一帧开始反应;面板内容最迟在约 400ms 内可读,整段不超过约 520ms。
5. **有因果。** 上台是「台子先到,小人落上去」;下台是「小人一蹬,台子才降」;完成是「台子接住小人」。

## 2. 分层与职责

| 层 | 负责 | 不负责 |
|---|---|---|
| 台子进度 `p` | 面板位移;手牌下沉与淡出;好友区域下边界;模块出现的时机;拖动与松手判定 | 小人姿势 |
| 自己小人的位置层(房间页内,独立于各房间页面) | 位置(漂浮点 ↔ 台面)、起跳弧线、缩放、名字行淡入淡出 | 骨骼姿势 |
| 骨骼 clip + 编排器 | 站立待机、蓄力、空中、落地这些姿势;运动 / 暂停 / 完成照旧 | 位置 |
| 面板模块 | 自己的出现动画、数字变化动画 | 知道小人或台子怎么动 |
| 手牌 | 下沉 / 升回、进入选卡、接住飞来的推荐卡 | 面板内容 |

模块和小人之间不直接通信:宿主在完成庆祝时按模块顺序发「节拍」,模块在自己的节拍上更新数字(见 §5.4)。

## 3. 几何

- **台面**:面板上沿。面板高度由内容决定,上限为屏幕高度的 `sheetMaxHeightFraction`(起始 0.45),超出部分在面板内滚动;只有把手和面板顶部一条响应拖动,内容区滚动不触发收起。
- **台上的位置**:水平居中;脚底比面板上沿高 `stageFootInset`(起始 6pt)。小人画在面板**后面**:脚下光圈的下半被面板挡住,像从台面后方透出的地灯;名字行在脚下,自然被面板挡住。这样不需要改小人的绘制,小人也永远不会盖住面板内容。
- **台上的大小**:`stageFigureScale`(起始 1.15),以脚底为原点缩放,和起跳同步变化。
- **漂浮点**:沿用现在的位置(收起态场景的 0.5, 0.55),按收起态的场景范围计算,不随面板展开移动,避免起跳目标在动。
- **好友区域**:下边界随 `p` 从「手牌上方」移到「面板上沿」,好友按比例上移。第 8 个好友的落点在下方正中,台上有小人时向侧面错开。
- **名字和状态行**:上台时随起跳淡出,下台落定后淡入。运动中的动作名与剩余时间已由顶部计时显示,台上不再重复。

## 4. 状态

位置状态(自己的小人):`漂浮` →(上台)→ `空中` → `台上` →(下台)→ `空中` → `漂浮`。`台上` 时小人高度 = 台面高度,跟着 `p` 走。

运动状态(待机 / 运动中 / 暂停)与位置状态相互独立,组合规则:

| 运动状态 | 上台 / 下台时的姿势 | 台上的 loop |
|---|---|---|
| 待机 | 蓄力 → 空中 → 落地回弹(新增 ×1 clip `board` / `leave`) | 站立待机(新增 loop `idle_stand`:无上下浮动,保留呼吸) |
| 运动中 | 不换姿势,运动 loop 继续,只移动位置 | 原运动 loop |
| 暂停 | 不换姿势,只移动位置 | 原暂停 loop |

编排器新增一个输入「是否在台上」和两个 ×1 反应;只在待机时生效。反应播放中若运动状态变化,沿用现有的「播完再按最新目标续接」。

## 5. 四段动画

时间为 1× 速度下的起始值。

### 5.1 上台(点自己的小人)

| 时刻 | 台子 / 手牌 / 模块 | 小人 |
|---|---|---|
| 0 | `p` 开始向 1(弹簧,约 320ms 到位);手牌随 `p` 下沉淡出 | 蓄力下蹲(约 90ms);轻触感反馈 |
| 90ms | — | 起跳:沿弧线飞向**台面当前位置**(落点每帧取实时台面),同时放大;名字行淡出 |
| `p` ≥ 0.7(约 200ms) | 模块依次出现,间隔 `sheetModuleStagger`(50ms),每个淡入 + 上移 8pt | — |
| 约 340ms | 台面被踩得下沉 `stageLandDip`(3pt)再弹回 | 落地:压扁回弹、脚下扩散环、轻触感;随后进入站立待机 |
| 约 520ms | 全部到位 | — |

### 5.2 下台(再点小人 / 点把手 / 点场景空白处)

| 时刻 | 台子 / 手牌 / 模块 | 小人 |
|---|---|---|
| 0 | 台子不动 | 蓄力下蹲(约 90ms) |
| 90ms | 被蹬下去:`p` 开始向 0;模块一起快速淡出(不分先后) | 起跳,弧线飞回漂浮点,略微冲过头再回落;缩回原大小 |
| `p` < 0.5 | 手牌升回、淡入 | — |
| 约 400ms | 手牌到位 | 落定,从浮动的起点开始上下浮动;名字行淡入 |

### 5.3 拖动把手

- 手指按住时 `p` 直接跟手(超过 1 有阻尼)。小人在台上时跟着台面一起下降。
- **小人在不在台上 = 松手后的结果。** 拖到 `p` < `stageDragLeave`(0.35)时小人自己跳下台回漂浮点(不蓄力);往回拖到 `p` > `stageDragBoard`(0.6)时小人跳回台上。两个阈值错开,避免在临界点来回跳。
- 松手:小人在台上 → `p` 回到 1;不在台上 → `p` 到 0。快速甩动按甩动方向判定,并让小人做相应的跳。
- 收起后没有可拖的把手;重新展开只能点小人。

### 5.4 今日推荐 → 选卡

2026-11-21 用户试用后决定:**先不做卡片飞行**(试过一版简化的飞行框,观感不对)。现在点今日推荐 = 面板降下、小人直接下台(不蓄力)、手牌以选卡布局出现且推荐卡在正中。卡片本身的动画以后单独优化。

- 推荐模块只能推荐当前手牌里的卡;宿主的「让手牌停在某张卡」动作在卡不在手牌时返回失败,此时只收起面板并进入普通选卡。

### 5.5 完成一张卡(领奖台)

目前卡只有「做完」一种结束方式;将来若加入中途结束,不升台,沿用现有的完成动作。完成时手牌正在选卡:不打断,退出选卡后按「欠一次庆祝」补播。

| 时刻 | 发生什么 |
|---|---|
| 0 | 台子升起(`p` → 1);小人保持最后的运动 loop,从漂浮点落向台面(无蓄力,约 260ms) |
| 落到台上 | 这时才把「已完成」交给编排器 → 播放现有的完成动作(跳起、双臂上举、扩散环 ×2) |
| 完成动作第一次落地(之后约 600ms) | 中等触感;发出第 1 个节拍,之后每个模块间隔 `celebrateBeatStagger`(120ms)依次收到节拍,在节拍上把数字从旧值滚到新值 |
| 完成动作结束 | 进入站立待机,面板保持展开 |

- 模块在收到节拍前继续显示旧值;若新数据还没到,数据到达时再变化,不等待。
- 面板本来就展开(小人已在台上):跳过升台,直接从「落到台上」开始。
- **完成时用户没在看**(App 在后台或锁屏):记为「欠一次庆祝」,下次回到房间页时补播一次;多次完成合并为一次,数字一次滚到最新。超过一定时间(可配置)不再补播,直接显示新值。
- 好友看到的仍然只是完成动作;台子是本机界面,不同步给别人。

## 6. 动画期间不接受操作

2026-11-21 用户真机试用后决定(取代原先「随时可打断」的设计):

- 面板升降或小人起跳进行中,点小人、点把手、点房间空白处、拖把手、点面板里的模块都不起作用;播完后才接受下一个操作。
- 手指正在拖把手时不算动画:小人在阈值处跳上跳下照常,松手后的归位动画期间才锁定。
- 程序自己发起的动作不受限制:完成庆祝、回到前台自动展开。
- 实现上保留了「从当前位置改目标」的能力(完成庆祝会在任意时刻发起),只是不把它开放给用户的手势。

## 7. 其他情况

| 情况 | 处理 |
|---|---|
| 冷启动进入房间页 | 面板直接是展开的,小人已在台上,不播上台动画;模块按各自数据就绪依次淡入 |
| 回到前台且规则要求自动展开 | 延迟约 200ms 播一次完整的上台动画(让用户看到面板是怎么来的);有欠的庆祝时改播 §5.5 |
| 左右滑切换房间 | 自己的小人(台上或漂浮)和台子都不动,只有房间和好友滑动 |
| 手牌正在选卡 / 牌组下拉打开 | 场景被遮罩盖住,点不到小人;关闭后才能上台 |
| 顶部出现连接提示条 | 不影响;好友区域上边界照旧 |
| 被移出房间 / 没有任何房间 | 面板与台子随房间页一起消失,不播动画 |
| 小屏 | 面板高度上限按屏幕比例,好友区域相应变矮;漂浮点与台面的距离变短,起跳弧高按距离等比缩小 |
| 系统开启「减弱动态效果」 | 不播弧线、压扁、飞行:面板短距离滑入并淡入,小人在两个位置间淡入淡出,模块同时出现,数字直接变化 |

## 8. 新增 token(起始值)

| 名称 | 起始值 | 含义 |
|---|---|---|
| `motion.stageSpring` | 约 320ms 到位、无回弹 | 台子升降的弹簧 |
| `motion.stageHop` | 250ms | 小人空中时间(上台);下台 310ms 可另设 |
| `motion.stageCrouch` | 90ms | 起跳前蓄力 |
| `motion.stageLand` | 180ms | 落地压扁回弹 |
| `motion.sheetModuleStagger` | 50ms | 模块依次出现的间隔 |
| `motion.celebrateBeatStagger` | 120ms | 完成庆祝时模块节拍间隔 |
| `decor.stageHopArc` | 16pt | 起跳弧高(小屏等比缩小) |
| `decor.stageFigureScale` | 1.15 | 台上小人放大倍率 |
| `decor.stageLandDip` | 3pt | 落地时台面下沉 |
| `decor.stageDragLeave` / `stageDragBoard` | 0.35 / 0.6 | 拖动时小人下台 / 上台的阈值 |
| `size.stageFootInset` | 6pt | 脚底高出面板上沿的距离 |
| `size.sheetMaxHeightFraction` | 0.45 | 面板高度上限(屏幕高度比例) |

卡片飞行沿用 `motion.playFly`,选卡过渡沿用 `motion.fanTransition`,完成动作沿用现有 clip。

## 9. 对现有结构的改动

- 自己的小人从各房间的场景里拿出来,放到房间页的独立一层(与面板、手牌同级);场景只画好友。`RoomScene` 增加「不画自己」的选项;登录前演示房间继续用原来的画法,不受影响。
- 小人动画指令增加「是否在台上」;clip 库增加 `idle_stand`、`board`、`leave` 三条数据;编排器增加两个只在待机时生效的 ×1 反应。渲染接口不变。
- 房间页现有的「场景下边距 = 手牌高度」改为随 `p` 变化。
- 完成事件先交给位置层(升台、落下),落到台上后再交给编排器。
- App 目前没有读取系统的「减弱动态效果」设置,本 change 引入。

## 10. 怎么验证动画

- 位置层的纯逻辑(阈值、松手判定、落点取实时台面、打断后的目标)写成不依赖界面的函数并做单测。
- debug 构建加一个慢放开关(全局放慢 5 倍),在模拟器和真机上逐段看;真机手感(拖动、触感)由用户确认。

## 11. 模块容器

新 feature `lib/features/home_sheet/`,按现有分层:

- **模块**:一个模块 = 一个 id + 一个页面级组件。模块自己读自己的数据,有内容时才画出外框;没有内容或出错时画空(容器不留间距)。模块向容器报告「加载中 / 有内容 / 无内容」,容器据此判断面板是否存在:全部无内容 → 面板不出现,小人不可点。
- **注册表**:id → 模块构造函数的一张表。布局配置里出现表里没有的 id 时跳过,所以旧版本遇到新模块不会出错。
- **宿主动作**(模块能对房间页做的全部事情):收起面板;让手牌停在某张卡(返回是否成功);打开某个页面。模块不引用房间页的任何其他东西。
- **节拍**:宿主在完成庆祝时按模块顺序依次发节拍;模块收到节拍前显示旧值,收到后把数字滚到新值。不关心数字的模块忽略节拍。
- **今日推荐**:推荐规则是一个可替换的策略(输入:当前手牌与运动记录;输出:一张手牌里的卡或无)。默认策略:手牌中最久没做过的一张,都没做过则取第一张。换规则只换策略,不动模块和容器。

## 12. 布局配置

一份配置决定模块清单与顺序、自动展开规则、补播庆祝的有效期:

```json
{
  "modules": ["recommendation"],
  "autoExpand": {"coldStart": true, "afterAwayMinutes": 30, "afterCompletion": true},
  "celebrationMaxAgeHours": 12
}
```

- 来源:沿用现有的远程开关机制,新增一个字符串参数 `home_sheet_layout`;App 内置同样形状的默认值。
- 读不到、不是合法 JSON、字段缺失或类型不对:整份或对应字段回退到内置默认值,不报错。
- `modules` 为空数组 = 关闭今日面板(房间页回到只有手牌的样子),可当作远程开关使用。
- 远程值在启动时读取,下一次启动生效(与现有开关一致)。

## 13. 自动展开与欠的庆祝

- **自动展开**是一个纯函数:输入(触发原因、上次离开房间页的时间、现在、配置)→ 是否展开。上次离开时间存在本机。
- **欠的庆祝**:完成被记录时如果房间页不在前台(或手牌正在选卡),在本机记下「欠 N 次、最近一次完成时间」;冷启动恢复过期会话时同样记下。回到房间页且没有遮罩时,若未超过有效期则播一次并清零,超过则直接清零。
- 两者同时成立时只播庆祝(庆祝本身会展开面板)。
