# Proposal: 伙伴开始运动时推一条通知——「你的「房间名」运动伙伴开始运动了!」

> State: in-progress · Updated: 2026-11-26

## Intent

CoFit 的核心是「和伙伴一起动」,但现在只有用户自己打开 App、恰好看到伙伴的小人在动,才知道对方在运动。App 不在前台时,伙伴开始运动这件最有社交价值的事完全传不出去,也就没有「他在动,我也动一下」的拉力。CoFit 现在不发任何通知。

做法是:房间里有人开始运动,就给同房间的其他人推一条通知,点开直接进那个房间。社交推送最怕刷屏,所以要按接收者限频,而且用户能整个关掉,或者只静音某个房间。

怎么知道有效:收到推送后点开的比例;点开后 30 分钟内出牌的比例;关闭推送 / 静音房间的比例(太烦会被关)。

## Scope

In scope:
- 伙伴(和我同在至少一个房间的人)开始一张卡时,我收到一条推送:哪个房间、谁开始运动了。
- 限频:同一个人每段冷却时间内最多收到一条这类推送,不管是哪个伙伴、哪个房间。冷却时长是内容(起步 3 小时)。
- 和同一个伙伴同在几个房间时只收一条;通知里的房间优先用对方出牌的那个房间。
- 点开推送直接进入通知里的那个房间。
- App 在前台时不弹这类推送(伙伴的小人本来就在眼前)。
- 「我的」里有总开关;房间菜单里可以静音这个房间。所有共同房间都被静音时,不收这位伙伴的推送。
- 第一次请求系统通知权限的时机放在有意义的时候;用户拒绝后,开关处说明如何去系统设置打开。
- 退出登录后,这台设备不再收到这个账号的推送;删除账号会清掉推送相关的数据。
- 文案(标题、正文)是可替换的内容。

Out of scope:
- 每日运动提醒(本机提醒,见 `add-workout-reminder`)。
- 「伙伴完成了」「伙伴给你点赞」等其他事件的推送,免打扰时段,按伙伴单独静音。
- App 内的通知中心 / 历史列表。
- 一起运动的邀请(「来一起做这张卡」)。

## Capabilities
- `partner-start-push`(new)

## Approach

开始一张卡时,客户端除了照旧在房间里广播,再在服务端留一条「开始运动」记录;服务端收到后找出这个人所有房间的其他成员,逐个检查开关、静音、冷却,再推到这些人登记过的设备上。限频与文案都在服务端,所以客户端改不了别人收到什么。这是 CoFit 第一次引入服务端代码和推送,需要用户开通付费方案、在 Apple 和 Firebase 后台配置推送证书,见 tasks.md 的 `me` 任务。

## Decisions
- 2026-11-26: 立项并开始实现 — 用户:社交 App 最重要的是加强用户之间的联系,以「你的「community name」运动伙伴开始运动了!」为例。
- 2026-11-26: 走 FCM + Cloud Functions,不走 Ably Push — 用户选择;服务端才能按接收者限频与静音,也避免 App 内嵌的 Ably key 被提取后被用来给所有人发推送。代价是需要 Blaze 方案和新增 functions 与部署 CI。
- 2026-11-26: 限频按接收者:每 N 小时最多 1 条,N 是内容 — 用户选择。起步 N = 3 是 agent 取的默认值,用户未确认。
- 2026-11-26: 设置做到「总开关 + 按房间静音」 — 用户选择。
- 2026-11-26: 首次请求通知权限放在「第一次完成一张卡、且所在房间里有其他人」之后;设置里的开关也能触发请求 — agent 的默认做法,用户未确认。
- 2026-11-26: 设置里的「通知」分组暂时只有这一个开关,沿用 10a「通知与隐私」的开关行样式;系统权限被拒时多一行「系统通知已关闭 · 去设置」 — agent 实现时的默认做法,用户未确认。
- 2026-11-26: 起步文案:标题为房间名,正文「你的「{房间名}」运动伙伴 {昵称} 开始运动了!」 — 依用户例句,可在配置里换。

## Open questions
