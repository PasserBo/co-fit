## Purpose

伙伴开始运动时,即使 App 不在前台,同房间的其他人也能知道并一步回到那个房间。推送按接收者限频,用户可以整体关闭或按房间静音。

## ADDED Requirements

### Requirement: 伙伴开始运动时推送
用户开始一张卡时,与他同在至少一个房间的其他成员必须收到一条推送,说明是哪个房间、哪位伙伴开始运动了。开始运动的人自己不收到。

#### Scenario: 同房间伙伴开始运动
- **GIVEN** 小林和小周同在房间「早起组」,小周开着推送且不在冷却中
- **WHEN** 小林在「早起组」开始一张卡
- **THEN** 小周的设备收到一条推送,写明「早起组」和小林的昵称
- **AND** 小林自己不收到这条推送

#### Scenario: 离线时开始的卡
- **GIVEN** 小林开始一张卡时没有网络,十几分钟后才恢复连接
- **WHEN** 开始运动的消息晚于开始时间超过 10 分钟才到达服务端
- **THEN** 不发推送

### Requirement: 每个伙伴只收一条
和开始运动的人同在多个房间的成员,每次必须只收到一条推送。推送里的房间优先是对方出牌的那个房间;那个房间不是共同房间或已被静音时,用另一个未静音的共同房间。

#### Scenario: 同在两个房间
- **GIVEN** 小林和小周同在「早起组」和「午休组」
- **WHEN** 小林在「午休组」开始一张卡
- **THEN** 小周只收到一条推送,房间写的是「午休组」

#### Scenario: 出牌的房间被静音
- **GIVEN** 小林和小周同在「早起组」和「午休组」,小周静音了「午休组」
- **WHEN** 小林在「午休组」开始一张卡
- **THEN** 小周收到一条推送,房间写的是「早起组」

### Requirement: 按接收者限频
每个用户在一段冷却时间内必须最多收到一条伙伴开始运动的推送,不管来自哪位伙伴、哪个房间。冷却时间从上一条推送发出时算起。

#### Scenario: 冷却中的第二位伙伴
- **GIVEN** 冷却时间为 3 小时,小周 1 小时前因小林开始运动收到过推送
- **WHEN** 同房间的小陈开始一张卡
- **THEN** 小周不收到推送

#### Scenario: 冷却结束
- **GIVEN** 冷却时间为 3 小时,小周 4 小时前收到过推送
- **WHEN** 小林又开始一张卡
- **THEN** 小周收到推送

### Requirement: 点开推送进入房间
点开推送时,App 必须打开并显示推送里的那个房间。用户已不在那个房间时,停在当前房间,不报错。

#### Scenario: 从后台点开
- **GIVEN** 小周的 App 在后台,当前显示的是「午休组」
- **WHEN** 小周点开写着「早起组」的推送
- **THEN** App 回到前台并切换到「早起组」

#### Scenario: 已退出那个房间
- **GIVEN** 小周收到推送后退出了「早起组」
- **WHEN** 小周点开这条推送
- **THEN** App 打开并停在当前房间

### Requirement: 前台不弹出
App 在前台时,伙伴开始运动的推送必须不显示横幅、不出声。

#### Scenario: 正在看房间
- **GIVEN** 小周正开着 App
- **WHEN** 小林开始一张卡
- **THEN** 小周的屏幕上不出现推送横幅

### Requirement: 推送总开关
用户必须能在「我的」里打开或关闭伙伴开始运动的推送。关闭后不再收到;重新打开后恢复。默认是开。

#### Scenario: 关闭推送
- **GIVEN** 小周在「我的」里关闭了伙伴开始运动的推送
- **WHEN** 同房间的小林开始一张卡
- **THEN** 小周不收到推送

#### Scenario: 系统权限未授予
- **GIVEN** 小周之前拒绝了系统通知权限
- **WHEN** 小周打开「我的」里的推送开关
- **THEN** 开关旁说明需要到系统设置里允许通知,并提供前往系统设置的入口

### Requirement: 按房间静音
用户必须能在房间菜单里静音或取消静音这个房间。静音的房间里伙伴开始运动不再产生推送;与某位伙伴的所有共同房间都被静音时,不收这位伙伴的推送。

#### Scenario: 静音唯一的共同房间
- **GIVEN** 小周和小林只同在「早起组」,小周静音了「早起组」
- **WHEN** 小林开始一张卡
- **THEN** 小周不收到推送

#### Scenario: 菜单显示当前状态
- **GIVEN** 小周静音了「早起组」
- **WHEN** 小周打开「早起组」的房间菜单
- **THEN** 菜单里显示「取消静音」

### Requirement: 首次请求通知权限
App 必须先用 App 内的提示说明通知的用处,用户在提示里选择打开后才弹出系统通知权限请求。提示必须在用户加入或新建一个房间之后出现(新建时在邀请卡收起后,文案说伙伴加入后开始运动会通知);已经在有其他成员的房间里、却从没被问过的用户,必须在打开 App 时看到同样的提示。选「以后再说」后 7 天内不再出现。系统权限已经问过(允许或拒绝)时不再出现。用户在「我的」里打开开关时,若系统权限尚未问过,直接弹系统请求。

#### Scenario: 加入房间后
- **GIVEN** 小周从没被问过通知权限
- **WHEN** 小周通过邀请加入「早起组」
- **THEN** App 内出现提示,说明打开通知后「早起组」里有人开始运动会第一时间知道

#### Scenario: 在提示里选择打开
- **GIVEN** App 内的通知提示正在显示
- **WHEN** 小周点「打开通知」
- **THEN** 弹出系统通知权限请求

#### Scenario: 以后再说
- **GIVEN** 小周在提示里选了「以后再说」
- **WHEN** 3 天后小周又加入了「午休组」
- **THEN** 不出现提示

#### Scenario: 更新前就在房间里的用户
- **GIVEN** 小周在更新前就和小林同在「早起组」,从没被问过通知权限
- **WHEN** 小周打开更新后的 App
- **THEN** App 内出现通知提示

#### Scenario: 新建房间
- **GIVEN** 小周从没被问过通知权限
- **WHEN** 小周新建了房间「夜跑组」,并关掉了邀请卡
- **THEN** App 内出现提示,说明伙伴加入「夜跑组」后开始运动会第一时间知道

### Requirement: 退出登录后不再收到
用户退出登录后,这台设备必须不再收到该账号的伙伴推送;删除账号时,推送相关的数据必须一并删除。

#### Scenario: 退出登录
- **GIVEN** 小周在这台设备上退出登录
- **WHEN** 同房间的小林开始一张卡
- **THEN** 这台设备不收到推送
