# Proposal: 用户能在独立页面建房并直接进入,也能浏览、搜索公开房间一键加入

> State: in-progress · Updated: 2026-11-19

## Intent

今天想进一个房间只有两条路:朋友发来的邀请链接,或者手动输入一串房间 ID。冷启动期大多数新用户没有已经在用 CoFit 的朋友,登录后面对的是空房间,唯一能做的是自己建一间然后等人——但别人也找不到它。建房也只是一个小 sheet,建完停在分享卡片,不会直接进房间。

本 change 让「房间」从只能靠熟人链接传播,变成可以被发现:愿意公开的房间出现在一个列表里,任何登录用户都能浏览、按名字搜索、一键加入;建房换成完整的页面,建好直接进入。

怎么知道它起作用了:TestFlight 测试者不靠邀请链接也能进入有其他人的房间;公开房间数量与「从列表加入」的次数(目前无埋点,先看 Firestore 里公开房间数与成员数)。

## Scope

In scope:
- 修复「我的房间」页左上返回按钮点了没反应(只有边缘右滑能关)。
- 独立的「新建房间」页面:房名(必填)、简介(可选)、可见性(公开 / 仅邀请,**默认公开**),带字数限制与说明文字;创建成功后直接进入该房间,并提示可以邀请朋友。
- 「发现房间」页面:列出公开房间(房名、简介、成员数、是否已加入),按成员数从多到少排序;顶部搜索框按房名/简介过滤;点进房间可看详情并一键加入,加入后直接进入该房间;已加入的房间显示「已加入」,点按直接进入。
- 入口:房间主界面无房间空态、「我的房间」页、「我的」页附近能到达「发现房间」与「新建房间」。
- 空态/失败/离线:无公开房间时引导去新建;加载失败可重试。

Out of scope:
- 加入审核、人数上限(2026-11-19 决议,见 Decisions)。
- 分类/标签、按地区或运动类型筛选、推荐算法、按「正在运动人数」排序。
- 服务端全文搜索(本期在已取回的公开房间里过滤)。
- 公共大厅 / 全球计数(另立 change)。
- 房间封面图、房间头像。

## Capabilities

- `room-creation`(new):建房页面与建房后的去向。
- `room-discovery`(new):公开房间的浏览、搜索与加入。
- 「我的房间」页返回按钮修复是 bug fix,不形成 spec 条目。

## Approach

同类社区型 App 的调研(见 design.md「调研」)归纳出的最小集合是:**建房表单(名字、简介、公开/私密)+ 公开列表(人数信号)+ 名称搜索 + 预览后一键加入**。分类、审核、上限、推荐都是房间多起来之后才有价值的东西。冷启动期公开房间很少,所以列表一次取完、在手机上排序与过滤即可;等公开房间数量上来再换服务端分页与搜索。

## Decisions

- 2026-11-13: 房间浏览先只做公开房间列表的子集(继承自 add-pre-signup-onboarding 的冷启动决议)。
- 2026-11-19: 新建房间默认「公开」— 冷启动期公开房间越多,发现页越不空;用户可切回仅邀请。
- 2026-11-19: 公开房间按成员数从多到少排序,同人数按创建时间新→旧 — 数据现成,不需要对每个房间做实时在线查询。
- 2026-11-19: 本期不设人数上限 — 冷启动期房间都很小,不改服务端规则。
- 2026-11-19: 从公开列表直接加入,不要房主审核 — 不想被陌生人加入就设为仅邀请;房主已可移出成员,成员可举报。

## Open questions

- 公开房间超过一次可取回的数量后,换成服务端分页 + 搜索(需要建索引)— 何时做看公开房间数。
