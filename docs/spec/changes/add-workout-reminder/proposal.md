# Proposal: 当天还没出牌才提醒——一天最多一条,用小人的口吻,点开直达房间

> State: idea · Updated: 2026-11-20

## Intent

没有好友在线时,App 没有任何主动把用户拉回来的触点:今天 CoFit 不发任何通知。调研里的研究结论是:提醒能把人带回 App,但对运动量本身的提升温和——要配合「一张卡就行」的低门槛才能转化。所以提醒要**克制且有条件**:只在当天还没完成时发,一天最多一条,点开后两步内就能开始一张卡。

怎么知道有效:收到提醒当天的出牌率、提醒关闭率(太烦会被关掉)。

## Scope

In scope:
- 用户选一个提醒时间,可随时关闭;默认开关状态是内容选择。
- 到点时,满足触发条件(如今天还没完成)才发一条通知;已完成则不发。
- 连胜即将中断时,文案相应变化。
- 文案用小人的口吻,不施压、不羞辱。
- 点开通知直接进入上次所在的房间,手牌展开。
- 第一次开启时请求系统通知权限;用户拒绝后,设置里说明如何去系统设置打开。
- 不需要网络:提醒在设备上排期。
- 触发条件(一张都没出 / 未达目标 / 连胜将断)与文案是可替换的配置。

Out of scope:
- 服务端推送、好友上线 / 好友开始运动的通知(另议)。
- 一天多条、按运动类型分别提醒。
- 主屏 / 锁屏小组件(调研 L1)。

## Capabilities
- `workout-reminder`(new)

## Approach

只做设备本地通知,不引入服务端推送。「今天是否已完成」和「连胜是否将断」分别依赖 `add-daily-card-goal` 与 `add-workout-streak`;本 change 可以先只依赖前者上线,连胜相关文案后补。

## Decisions
- 2026-11-20: 由运动记录竞品调研(H3)立为提案 — 没人在线时唯一的主动触点,成本低、收益确定。
- 2026-11-20: 指标、目标值、规则参数都是**可随时调整的内容**,本系列不在提案里定死;要求系统足够解耦——计量方式、目标、连胜规则、解锁表、提醒文案各自独立可换,改一处不牵动其他部分 — 用户:先把系统做出来,再决定提供什么内容。

## Open questions
