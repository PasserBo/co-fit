# Proposal: 宽容的运动连胜 + 运动日历——坚持过的日子看得见,偶尔断一次不清零

> State: idea · Updated: 2026-11-20

## Intent

「今日出牌环」解决当天的理由;连胜解决「明天还回来」的理由——用户会不想失去已经攒下的 N 天/N 周。但硬性每日连胜一断就清零,断掉后用户往往直接放弃(Duolingo 因此做了冻结,Hevy/Strava 干脆按周计)。CoFit 需要一个**宽容**的连胜,并配一张日历把坚持可视化,成为连胜的「证据页」。

怎么知道有效:有连胜的用户 7 日 / 28 日回访率,与断连后是否还会重新开始。

## Scope

In scope:
- 连胜作为「今日面板」(`add-home-sheet`)的一个模块,同时显示在运动历史页顶部。
- 宽容规则:偶尔断一次不清零(按周计、按天计 + 冻结等都应能作为规则接入,起步用哪种是内容选择)。
- 每个周期第一次完成时,提示「第 N 周(天)连胜」。
- 断连后不显示刺眼的 0,而是给「重新开始」的提示;同时保留「最长连胜」。
- 运动历史页加日历/热力图:出过牌的日子被点亮,深浅表示出牌数;可以往前翻看。
- 日界按用户本地时间的自然日。
- 连胜规则(按周 / 按天 / 冻结次数 / 门槛)是可替换的规则,换规则不改展示与数据记录。

Out of scope:
- 补记过去的运动、付费买冻结。
- 好友之间比连胜、排行榜。
- 周报/月报与分享卡(调研 M2,另立)。

## Capabilities
- `workout-streak`(new)
- `workout-history`(new:运动历史页第一次有主规格,本 change 带上日历部分)

## Approach

现在运动历史只读最近 100 条记录,算不出长连胜和「最长连胜」,也画不了整年日历;本 change 需要一份随出牌同步更新的个人运动汇总(累计数、当前/最长连胜、最后活跃日),记录里也要补「用户本地日期」。这些是数据层改动,立项后在 design.md 一次性规划,服务端规则改动按惯例先给用户看 diff。

## Decisions
- 2026-11-20: 由运动记录竞品调研(H2 + H5 的日历部分)立为提案 — 硬性日连胜断掉即流失,做宽容版。
- 2026-11-20: 指标、目标值、规则参数都是**可随时调整的内容**,本系列不在提案里定死;要求系统足够解耦——计量方式、目标、连胜规则、解锁表、提醒文案各自独立可换,改一处不牵动其他部分 — 用户:先把系统做出来,再决定提供什么内容。
