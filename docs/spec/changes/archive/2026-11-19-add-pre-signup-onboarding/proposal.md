# Proposal: 新用户在登录前就能在演示房间里打出一张卡、看小人动起来,然后再被邀请登录

> State: done · Updated: 2026-11-18

## Intent

今天新用户打开 CoFit 看到的第一屏是登录页,交出 Apple ID 之后是起名,然后是一个没有任何人的空房间。产品的核心(虚拟小人 + 打出卡牌开始运动)在用户做出任何承诺之前完全没有露面。冷启动期没有好友、没有房间,这个空房间也无法靠「有人在」来补救。

这是三个冷启动方案(房间浏览 / 登录前引导 / 公共大厅)里唯一不依赖其他用户就能把核心体验展示出来的方案,所以先做它。目标:用户在登录前就完整走一遍「看到自己的小人 → 打出一张卡 → 小人做动作 → 结束」,再被邀请登录,把漏斗里「登录」这一步挪到产品已经证明自己之后。

怎么知道它起作用了:首次启动到完成登录的比例上升,登录后的空房间不再是第一印象。目前没有埋点,先以 TestFlight 测试者的口头反馈为准。

## Scope

In scope:
- 首次启动时,未登录用户先进入一个**演示房间**,里面有自己的小人(待机)、一手演示用的动作卡,以及 2–3 个明确标注为「示例」的小人在做不同动作。
- 用户在演示房间里可以像正式房间一样聚焦手牌、上滑打出一张卡,小人进入该动作、显示倒计时、结束后回到待机;演示里的倒计时缩短到约 10 秒,并提示用户演示已缩短。
- 演示过程中有少量引导文案,告诉用户「这是你的小人」「上滑打出卡牌开始运动」「好友会以小人形式出现在同一个房间」。
- 演示结束(打出至少一张卡,或用户主动结束)后出现邀请登录的入口,进入现有登录页;登录后流程不变(起名 → 主界面)。
- 演示房间不需要网络,离线也能完整走通。
- 演示右上角可随时「跳过」直接去登录页;看过或跳过之后,再次启动直接进登录页,不再出现。
- 通过邀请链接冷启动的未登录用户,仍按现有流程处理(链接滞留,登录后弹预览),不被演示打断或丢失。

Out of scope:
- 不改登录页和起名页本身的内容与顺序。
- 演示里打出的卡**不**记入运动历史,不产生任何云端数据。
- 不做形象定制、不在演示里让用户起名。
- 不做房间浏览、公共大厅、全球计数(另立 change)。
- 不加埋点/统计(另立 change)。

## Capabilities

- `welcome-tour`(new):登录前的演示房间与引导。
- 现有的登录与起名流程不变,不作为本 change 的 capability。

## Approach

演示房间复用正式房间的场景与手牌组件,只喂本地固定数据:自己的小人、一组内置的官方动作卡。打出卡牌走正式的「起手 → 运动循环 → 完成」状态机,但不写云端、不广播给任何人。引导文案以轻量 overlay 的形式按步骤出现,不做多页向导。

## Decisions

- 2026-11-13: 三个冷启动方案中优先做登录前引导,房间浏览只做公开房间列表子集、公共大厅降级为全球计数,二者另立 change — 冷启动期没有其他用户,只有引导方案不依赖「有人在」。
- 2026-11-13: 演示房间离线、不产生云端数据 — 登录前没有身份,也不希望演示数据污染正式数据。
- 2026-11-13: 演示房间放 2–3 个标注「示例」的小人在运动 — 只靠文案讲不清「好友会出现在同一房间」;标注是为了不冒充真实用户。
- 2026-11-13: 演示可跳过,且只出现一次 — 急性子用户和审核员都不该被强制走完;再次启动不再打扰。
- 2026-11-13: 演示里的倒计时缩短到约 10 秒并提示已缩短 — 完整走完「起手→运动→完成」动画即可,真实时长会让人等得不耐烦。
- 2026-11-18: 真机走查通过,1.0.0 (3) 上传 TestFlight,change 完成归档 — 埋点与登录转化率另立 change 时再看。
